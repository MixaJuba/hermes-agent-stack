## Чого вже торкалися зміни

Працюємо лише з цим хмарним checkout. Ноутбук користувача не підключений і не
змінюється. Базова перевірка не встановлює Hermes, не підключає оплату, не створює
серверів, не витрачає токени inference і кредити вебпошуку. Файли репозиторію
не означають, що бот запущений. Новий Git worktree не потрібний.

## Необхідні особисті дії

1. Уже виконано: мережу налаштовано, ключ NVIDIA додано захищено, середовище
   успішно опубліковано. Обов'язкову незаповнену вимогу Exa видалено; не
   повертати її до етапу налаштування вебпошуку. Нову публікацію не запускати.
2. Користувач уже особисто увійшов у [NVIDIA Build](https://build.nvidia.com/).
   Залишається перевірити квоту, строк дії та відповідність trial-умовам.
   Ключ повторно не потрібний. Не надсилати його в чат або Git.
   Перевірка каталогу не підтверджує підтримку інструментів або готовність бота.
3. Після підтвердження безкоштовного модельного доступу — особиста реєстрація
   [Oracle Free Tier](https://www.oracle.com/cloud/free/) та перевірка Always Free
   у домашньому регіоні. На запит картки, тимчасового блокування коштів,
   платного плану або персональної перевірки агент зупиняється. Користувач
   перевіряє й проходить ці кроки сам. Не вводимо особистих даних замість нього.
4. Зареєструвати [Exa](https://exa.ai/), перевірити безкоштовні кредити,
   тарифікацію search/contents, поновлення та відсутність оплати й автопоповнення.
   Ключ вводиться в захищене поле `EXA_API_KEY`.
5. За повідомленням локального координатора, офіційний
   [BotFather](https://t.me/BotFather) уже створив `@mixa_hermes_ua_bot`;
   повторно не створювати. Ботовий токен
   зберігається захищено на цільовому сервері; його не вставляємо в чат,
   команди, звіти або репозиторій. Перед запуском підтверджуємо Telegram ID
   власника за контрольним повідомленням. Незнайомого першого відправника
   автоматично власником не призначаємо.

Ці кроки виконуються послідовно з перевіркою після кожного. Не потрібно
одночасно створювати всі акаунти до підтвердження модельного маршруту.
За відсутності Always Free сервера повідомляємо блокер. Локальний запуск на
ноутбуці та платні альтернативи не застосовуються.

## Безпечне продовження

- Секрети, надані через проксі Codex, можуть бути підставними значеннями,
  які замінюються лише під час запиту до дозволеного HTTPS API. Не друкуємо,
  не перевіряємо їх вигляд і не переносимо ці значення у конфігурацію сервера.
- Наявність змінної не доводить валідність ключа; потрібен реальний дозволений
  запит. Невідома або відсутня квота не означає безліміт.
- Не знімаємо мережеві обмеження обходом проксі, не вимикаємо TLS і перевірку
  артефактів. Додаткові домени дозволяємо адресно через налаштування.
- Діагностика не виводить відповіді API, ключі, заголовки авторизації або
  необроблені помилки. Перенаправлення автентифікованих запитів заборонене.
- Факти про акаунт, які неможливо отримати через офіційне API, перевіряємо
  в особистому кабінеті користувача; не підміняємо їх загальними тарифами.
- Автоматичний резервний пошук Hermes вимкнути (`web.keyless_fallback: false`),
  пошук закріпити за перевіреним Exa. Резервні модельні провайдери вимкнути;
  допоміжні виклики спрямувати лише до дозволеної безкоштовної моделі.
- Groq не є основою агента. Голосові сервіси, ElevenLabs, River і платні
  сторонні gateway на цьому етапі не підключаємо.

## Умови перед розгортанням

- Точний API ID моделі, безкоштовні умови прототипування й доступна квота
  підтверджені для цього акаунта. Успішний GET каталогу цього не замінює.
- Встановлення з офіційного закріпленого джерела з його PM-керованим Python;
  перевірена фактично встановлена версія. Не вважати системний Python 3.12
  достатнім для поточного first-party встановлення Hermes.
- Підтримувані API-параметри, повний системний запит, схеми інструментів,
  контекст і запас відповіді відповідають лімітам провайдера.
- Реальний цикл саме Hermes: модель -> tool call -> виконання -> tool result ->
  завершальна відповідь. Окремий приклад виклику OpenAI-сумісного API не є
  підтвердженням працездатності всього Hermes.
- Oracle підтверджує безкоштовність і наявність VM, диска та резервного
  сховища; пробні $300 не враховуються як постійний безкоштовний тариф.

## Приймання готового бота

Розгортання на Oracle має використовувати окремого непривілейованого
користувача, ізольований контейнер для команд і файлів, один Telegram poller
через long polling і systemd для автозапуску та відновлення після збою.
Контейнер інструментів не отримує ключів, Docker socket або метаданих Oracle.
Контекст і пам'ять зберігаються на постійному диску. Резервні копії поза VM
допускаються лише в межах підтвердженої безкоштовної квоти приватного сховища.

Після доступу до моделі та сервера перевіряємо:

1. Українську відповідь у Telegram і контекст кількох повідомлень.
2. Виконання інструмента й вебпошук Exa з посиланнями з реальних результатів.
3. Відмову сторонньому Telegram ID та недоступність секретів із інструментів.
4. Контекст після перезапуску процесу й сервера, відновлення з резервної копії.
5. Імітовані 402/429 і вичерпання квоти без витрачання реальної квоти до нуля:
   обмежені повтори, зрозуміле повідомлення, жодного переходу на оплату.

Тести діагностики в `tests/` не є цими наскрізними перевірками. Готовність
підтверджується лише окремими фактичними результатами всіх потрібних перевірок.
