# Підсумок для продовження hermes-agent-stack

Оновлено: **1 листопада 2026 року**. Це передавання контексту, а не звіт про
готового бота. **Бот ще не встановлений і не розгорнутий.** Перед новими діями
звірити фактичні файли, стан середовища й доступні інструменти.

## Мета та незмінні умови

- Персональний текстовий Telegram-бот українською на офіційному Hermes Agent
  від Nous Research: контекст між повідомленнями, пам'ять, виконання завдань
  інструментами, вебпошук Exa з посиланнями.
- Бюджет **0 грн**. Без оплати, автопоповнення, платних резервних моделей або
  ресурсів, що стають платними після пробного періоду. Невідома квота не є
  безлімітом; при недоступності безкоштовного доступу повідомити точний блокер.
- Цільовий сервер — **Oracle Always Free**. Не підміняти його пробними $300.
  На ноутбук користувача нічого не встановлювати, локальний запуск виключений.
  Acer Aspire E5-573G / Windows 10 відомі зі слів користувача, не з діагностики.
- Модель першого вибору — DeepSeek V4.1 Flash через NVIDIA NIM. Groq не є
  стандартною основою Hermes. River допускався лише як необов'язковий варіант
  на підтверджених бонусах без списань; зараз його не підключено.
- Голос, STT/TTS, ElevenLabs і великі локальні моделі не потрібні. Використати
  штатний Telegram gateway Hermes; Telethon з початкового README не потрібен.
- Доступ бота — лише за підтвердженим числовим Telegram ID власника.
- Виконувати доступні роботи самостійно. Особисті входи, перевірки особи,
  картку та безпечне введення секретів виконує користувач. На запит картки,
  тимчасового блокування коштів або платного плану зупинитися для його дії.
- Паролі й ключі не приймати в чат, не друкувати в логах і не зберігати в Git.
  Проксі-значення секретів Codex не копіювати у серверні конфігурації.

## Що фактично зроблено

1. У `/workspace/hermes-agent-stack` є робоча копія
   `MixaJuba/hermes-agent-stack`. Спочатку репозиторій містив лише README;
   базовий коміт перед підготовкою цих файлів — `9b37483`. Код, документацію
   й це резюме користувач доручив зберегти на GitHub. Поточний стан
   синхронізації перевіряти через Git, а не за старими повідомленнями чату.
2. Додано `.gitignore`, порожній `.env.example`, джерело Hermes у
   `config/upstream.json`, діагностику `scripts/check_access.py`, інструкцію
   `docs/SETUP.uk.md`, початковий звіт і тести. Діагностика робить тільки GET,
   не запускає inference, пошук або створення серверів і не виводить секретів.
3. **10 тестів діагностики пройшли.** Це тести безпеки й поведінки перевірок
   доступу, не наскрізні тести бота.
4. Початково проксі блокував NVIDIA, Exa й Oracle. Після налаштування мережі
   реальні GET-запити до каталогу NVIDIA, документації Oracle й тарифів Exa
   повернули HTTP 200. Каталог містить **`deepseek-ai/deepseek-v4.1-flash`**.
   Це не підтверджує працездатність генерації, інструментів або квоти акаунта.
5. Користувач додав `NVIDIA_API_KEY` у захищене поле. При поточній перевірці
   середовище працює, мережеві правила застосовані, binding NVIDIA має стан
   `ready`, змінна присутня. Значення ключа не розкривалося.
6. Публікація середовища спочатку не вдавалася. У чернетці була обов'язкова,
   але незаповнена вимога Exa. **Після її видалення користувач підтвердив
   успішну публікацію.** Технічного журналу першопричини не отримано; не
   видавати послідовність подій за доведений внутрішній діагноз платформи.
   Не додавати обов'язковий `EXA_API_KEY` повторно до етапу підключення Exa.
7. Збережено ZIP із усіма тодішніми 8 файлами, Git-історією та контрольними
   сумами. Копію відновлено в окрему папку, хеші збіглися, 10 тестів пройшли.
   **Користувач підтвердив завантаження архіву на свій комп'ютер.** Це не
   встановлення програм на ноутбук. Старий архів не містить цього нового резюме.
8. Офіційний вихідний код Hermes **v0.22.5** клоновано як залежність у
   `/workspace/.hermes-runtime/source`. HEAD перевірений:
   `bf0203a794a07aac3ff764972ab9087baa4e4f4e`.
   **Робочий runtime, його залежності й керований Python ще не встановлені.**
   Для поточного first-party встановлення потрібен PM-керований Python 3.14;
   системний Python 3.12 не вважати готовим runtime Hermes. Використовувати
   офіційний PM і lockfiles, не змінювати середовище Hermes сирими pip/uv.

## NVIDIA: підтверджені умови та відкриті питання

- Офіційна [сторінка моделі](https://build.nvidia.com/deepseek-ai/deepseek-v4.1-flash)
  позначала Free Endpoint як Available, із безкоштовним прототипуванням.
  [Модельна карта Markdown](https://build.nvidia.com/deepseek-ai/deepseek-v4.1-flash.md)
  указує підтримку function calling і комбінований контекст 1 048 576 токенів.
  Це опис моделі, не виміряний ліміт конкретного hosted API або акаунта.
- Прочитано пов'язаний зі сторінки офіційний
  [NVIDIA API Trial Terms of Service](https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf).
  Пункти **1.2 і 1.4** обмежують hosted trial внутрішнім тестуванням та
  оцінюванням, виключають production без окремої підписки й допускають
  обмеження часу/кредитів. Є обмеження на передавання чутливих і персональних
  даних. Ліцензія самої моделі не скасовує умов hosted сервісу.
- Отже, **постійний безкоштовний персональний бот на цьому endpoint ще не
  обґрунтований**. Потрібно розрізнити дозволений тестовий прототип і подальшу
  експлуатацію. Не обіцяти безкоштовність назавжди і не переходити на оплату.
- Квоти, залишок кредитів і строк доступу саме цього акаунта не отримані.
  Користувач повідомив, що особисто увійшов у NVIDIA Build у вбудованій вкладці.
  Пропозицію передати пароль відхилено; пароль не потрібний і не передавався.
- При останній перевірці не було інструментів керування авторизованою вкладкою,
  а службове підключення браузера не було активним. **Пізніше в каталозі навичок
  з'явилась `browser-act:browser-act`; її можливості ще не перевіряли.** Перед
  висновком, що браузер недоступний зараз, прочитати цю навичку й перевірити
  підтримуваний інтерфейс. Новий окремий браузер не прирівнювати до вкладки
  користувача. Не читати cookie/profile-файли й не переносити авторизацію.

## Що не зроблено

- Жодного реального POST inference, перевірки української генерації або
  використання `usage`/rate-limit headers. Нуль підтверджених циклів інструментів.
- Немає вимірювання повного системного запиту Hermes з усіма запланованими
  схемами інструментів, пам'яттю та запасом для відповіді.
- Oracle VM, мережа й резервне сховище не створювалися. Доступ до акаунта,
  домашній регіон, квоти й наявність Always Free сервера не перевірені.
  Поточний Codex Linux — **не сервер Oracle для майбутнього бота**.
- Exa не підключено; `EXA_API_KEY` відсутній. Реальні пошуки не виконувалися.
- Telegram не підключено; `TELEGRAM_BOT_TOKEN` відсутній, ID власника не
  підтверджено. Створення бота користувачем не підтверджене.
- Немає готової runtime-конфігурації Hermes, service/autostart, резервування
  працюючого бота, перевірок відновлення його пам'яті або вичерпання квот.
- Нічого не встановлювалося на ноутбук і не підключалося до оплати.
- Відео використовувалося як орієнтир за кадрами й субтитрами; аудіотранскрипцію
  не робили. Користувач зупинив подальший аналіз відео; не відновлювати його.

## Наступні дії в погодженому порядку

1. Перевірити стан поточної сесії й нові можливості browser-act. Якщо доступна
   саме авторизована вкладка, лише прочитати квоти/ліміти/строк, не змінювати
   акаунт. Інакше отримати ці дані зі скріншота користувача або офіційного API;
   невідоме залишити невідомим. Врахувати trial-обмеження перед розгортанням.
2. У дозволеному безкоштовному тестовому режимі виконати короткий запит до
   офіційного endpoint із гранично обмеженою відповіддю та без особистих даних.
   Зафіксувати HTTP-статус, результат, usage і надані ліміти. На 402/вичерпанні
   зупинитися, на 429 — обмежені повтори; без платного fallback.
3. Підготувати офіційний PM-runtime закріпленого Hermes у хмарі, без голосу,
   desktop/browser/computer-use компонентів, непотрібних цьому текстовому боту.
   Перевірити встановлену версію, а не лише тег вихідного коду.
4. Через **сам Hermes** виконати цикл: модель -> tool call -> безпечне виконання
   -> tool result -> фінальна відповідь. Потім перевірити запланований набір
   інструментів, розмір повного запиту й відповідність фактичним лімітам API.
   Прикладу з окремою функцією через SDK для цього недостатньо.
5. Після проходження модельного етапу — особистий доступ користувача до Oracle,
   перевірка Always Free і розгортання без платних ресурсів. Якщо безкоштовного
   сервера немає, повідомити блокер, без перенесення виконання на ноутбук.
6. Підключити перевірений безкоштовний Exa, вимкнути автоматичну ротацію
   пошукових сервісів і платні/непідтверджені допоміжні моделі. Підключити
   Telegram long polling із єдиним owner ID. Налаштувати ізольовані інструменти,
   постійну пам'ять, systemd, обмежені retries, журнали без секретів і резерви
   лише в межах підтвердженої безкоштовної квоти.
7. Пройти E2E: український діалог, контекст, реальні інструменти, пошук із
   посиланнями, відмова сторонньому ID, перезапуск процесу й сервера,
   відновлення з резерву, імітація вичерпання квот без реального виснаження.
   До цього бот **не готовий**.

## Як повернутися до роботи без повторення вже зробленого

- Прочитати цей файл, `README.md`, `docs/SETUP.uk.md` і стан Git. Не створювати
  новий worktree й не скидати наявні зміни. Резерв перед видаленням/перестворенням.
- `reports/access-check.json` — **історичний звіт до застосування доступів**:
  відсутній у ньому ключ і proxy denial уже не описують поточний стан.
  `config/upstream.json` має `verified_model_id: null`, бо повна модельна
  перевірка не виконана; знайдений у каталозі ID вказаний у цьому резюме.
- Додаткові матеріали поточної машини: `/workspace/recovery/` (початковий ZIP,
  контрольна сума, звіти доступу та відновлення), `/tmp/hermes-nvidia-check/`
  (отримані офіційні trial-умови). Ці шляхи можуть не зберегтися на іншій машині.
- Збереження чернетки, застосування runtime-змін і публікація — різні події.
  Не повторювати старі зміни й не публікувати середовище автоматично.
- Окремий платний акаунт Hermes / Nous Portal для цього плану не потрібний.
  Чати не мають гарантованого доступу до історії один одного: передати цей
  файл явно. Відкрита вкладка також не гарантує доступу агента до неї.

Для перевірки тільки діагностики (не бота):

```bash
cd /workspace/hermes-agent-stack
python3 -m unittest discover -s tests -v
python3 scripts/check_access.py
```

Очікуваний код останньої команди зараз — `2`: Exa, Telegram та owner ID ще
відсутні. Це не свідчення несправності вже підключеної NVIDIA. Після появи
всіх секретів навіть код `0` підтверджує тільки доступи, не готовність бота.
