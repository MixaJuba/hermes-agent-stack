**Що змінив H-005L:** за звітом Local активний SOUL входить у контекст; невдалий пошук пояснюється ізоляцією Docker. Підтверджено зайве уточнення після успішного інструмента; створення файла ще не гарантує доставки. Нових Telegram E2E не виконували, приватні квоти й Oracle Console не перевірені. Повний операторський звіт не публікується.

**Правило статусів для Issues / майбутньої дошки Projects:** **Заплановано** — роботу визначено; **Виконується** — є підтверджений початок; **Очікує перевірки** — результат подано на приймання; **Завершено** — результат прийнятий із посиланням на доказ. GitHub Issue закривається лише після приймання; злиття PR саме по собі не означає розгортання на сервері. **Окрема дошка GitHub Projects ще не налаштована** — не плутати її з цією Markdown-сторінкою.

## Як працювати далі

На початку сеансу відкрий **«Поточний стан»**, потім [відповідний Issue](https://github.com/MixaJuba/hermes-agent-stack/issues) і лише [канонічний стан](../PROJECT_STATE.md) та один потрібний доказ. Не перечитуй усю історію без конкретної невідповідності. Виконання ведеться через Issues/PR; після прийнятої зміни координатор одночасно актуалізує цей короткий огляд і `PROJECT_STATE.md`. Правила Codex — [`AGENTS.md`](../AGENTS.md), передача контексту — [`PROJECT_HANDOFF.md`](../PROJECT_HANDOFF.md).

**Публічна безпека:** жодних токенів, приватних ключів, персональних даних, внутрішніх ідентифікаторів чи приватних журналів. **GitHub `main` ≠ фактичний стан Oracle зараз.**
