# H-004L. Документи й одноразові нагадування Bro

## Конфігурація

- Залишається Hermes v0.22.5, Workers AI GLM-4.7-Flash, keyed Exa та один Telegram gateway для власника.
- H-003L використовує `web_search_recent` із київським часовим вікном. Guard допускає лише ті додаткові пакети, чиї файли звірив з еталоном. Він підтримує YAML, який Hermes зберігає після штатних змін профілю.
- Пакет активує штатні скіли й todo для Telegram. Пам’ять, пошук сесій і вебінструменти вже входили в baseline. PDF, DOCX, XLSX, PowerPoint, grounded-citations і weekly-review-planning постачає Hermes. Пакети сторонніх скілів не потрібні.
- Окремий ARM64-образ `hermes-ua-sandbox:documents-v1` містить бібліотеки PDF, DOCX, XLSX і PPTX. Для CSV використовується стандартний Python. Мережа контейнера вимкнена, користувач непривілейований. Вхідні вкладення йдуть штатним read-only кешем Hermes.
- Для доставки пакет використовує наявний persistent Docker workspace. Дозволена папка результатів — `/workspace/out`, на хості вона належить `hermes-agent` і має права `0700`. Доставка перевіряє власника Telegram DM, імена, свіжість і розмір файлів. Приймає до трьох документів по 8 МіБ. Надсилає їх через штатний відправник Hermes і повертає підтверджені імена.
- Нагадування лише в особистий чат власника, від 1 хвилини до 7 діб, одне очікує одночасно. Hermes Cron доставляє текст скрипта один раз без inference. Загальний `cronjob_manage` у Telegram вимкнений.
- Аналіз і генерацію зображень відкладено за рішенням власника. Для PDF перевірено текстовий шар. OCR сканів не кваліфіковано.

## Відтворення

1. На Oracle зібрати образ із цього Git-дерева командою `docker build -t hermes-ua-sandbox:documents-v1 -f deploy/Dockerfile.capabilities deploy`. Інтернет потрібен лише для складання образу з Debian і PyPI. Для виконання залишити `docker_network: false`.
2. Підготувати підкаталог `out` у штатному persistent Docker workspace з власником `hermes-agent` і правами `0700`. На цьому профілі хостовий шлях визначений у `deploy/hermes-config.json`. Для нового хоста перевірити шлях до активації.
3. Звірити й установити пакети в еталоні `deploy/plugins` та в активному профілі. Для чинного профілю зберегти всі дані й застосувати лише потрібні поля з шаблона. `render_config.py` призначений для нового профілю.
4. Підготувати копії файлів для відкату, запустити guard, дочекатися завершення активного ходу й перезапустити один сервіс. Підтвердити підключення Telegram, єдиний poller і приймання та доставку контрольних документів.

## Перевірка на Oracle і в Telegram

- Початковий профіль мав 53 увімкнені штатні скіли, але Telegram toolset не включав `skills`, `todo` або нагадування. Пам’ять, пошук сесій, Docker terminal і Exa працювали у прийнятому baseline.
- Після запуску H-003L Telegram отримав точний 48-годинний проміжок і повідомив про нуль підтверджених результатів. Окремий контроль за 96 годин повернув пряму статтю ДСНС, дату 06.11.2026 08:38 і правильні межі. Інструмент і джерело звірено.
- Синтетичний PDF доставлено в Telegram і прочитано. Bro повернув код із документа й дві дії з виконавцями та термінами. Читання пам’яті підтвердило раніше збережений контрольний факт.
- Одноразове нагадування фактично прийшло власнику. Запис Hermes Cron завершений, один запуск з одного, `no_agent=true`.
- PDF, DOCX і XLSX реально надійшли трьома вкладеннями після явного виклику `bro_send_documents`. У звичайному запиті модель створила файли, але не викликала доставку автоматично. Повторне читання підтвердило текст і числа в DOCX та клітинки й формулу в XLSX. У PDF числа правильні, проте точний український заголовок не підтвердився. Наскрізний сценарій з одного запиту має статус PARTIAL.
- Контроль образу ARM64 підтвердив створення і повторне читання PDF із кирилицею, DOCX, XLSX і PPTX. Підсумковий Linux regression дав 69 пройдених і 7 пропущених тестів.
- На Oracle відбулися три контрольовані перезапуски. Перший для H-003L, другий для пакета документів і нагадувань, третій для вузького інструмента доставки. Guard пройшов, один poller, відкат не знадобився.
